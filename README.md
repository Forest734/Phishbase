# Phishbase

Browse Phish setlists by year, tour, show and song, with show notes, photos
and the Stats page. Express 5 serves a JSON API plus a no-build front end in
`public/`. It is [Deadbase](https://github.com/Forest734/Deadbase), the
Grateful Dead version, remade for Phish.

```sh
npm install
npm run dev      # http://localhost:3000 (PORT overrides), restarts on change
npm test
npm run build    # the static GitHub Pages site, into dist/
```

## What's in it

- **Years, Tours, Songs and show pages.** Every show from 1983 to 2026 by year,
  each with its setlist underneath, and ★ on the versions picked for
  Phish.net's Jam Charts. Every tour, and every song with the shows it was
  played at (covers name their original artist). Long show lists have a
  shows-per-month (or per-year) chart whose columns narrow them, and runs of
  shows at one venue are tagged.
- **Show notes.** Each show page has its setlist with song lengths, and under
  each song the notes on it: Jam Charts write-ups, guests, teases, debuts,
  bustouts, alternate lyrics, secret-language signals, banter. Then the notes
  on the show itself (stage lore, costumes, weather), and the taper notes that
  came with the recording. Tags link to every show that has them.
- **Photos and cover art.** Concert photos from Wikimedia Commons on the shows
  they were taken at, each credited to its photographer with its licence; and
  phish.in's generated cover art for every show with a recording, plus a link
  to listen there.
- **Stats.** Charts for any range of years or era (1.0, 2.0, 3.0, 4.0), for the
  whole band or for one state, country or venue: shows per year and month,
  songs in rotation, Jam Charts leaders, show features, openers, encores, where
  they played, and records. Every bar, cell and tile links to the shows behind
  it.
- **Search** by venue, city, state, country, tour or date, and **Start over**
  in the header to get back to the home page with nothing filtered.

Pages are hash routes (`#/year/1997`, `#/show/1997-11-22`,
`#/song/you-enjoy-myself`, `#/shows?tour=fall-tour-1997`,
`#/stats?state=VT&from=1983&to=2000-10-07`), so any view can be bookmarked or
shared.

## Data

Everything the app shows is in `data/`, generated by two importers and
committed, so the app needs no network access for its data. (Cover art and
photos are images linked from phish.in and Wikimedia Commons.)

**Setlists and notes** come from [phish.in](https://phish.in), an open-source
archive of live Phish recordings ([code](https://github.com/jcraigk/phishin),
MIT), through its free [API v2](https://phish.in/api/v2/swagger_doc), which needs no key.
It covers every known show, including those with no circulating recording.
The Jam Charts notes it carries are from [Phish.net](https://phish.net/jamcharts)
and the Mockingbird Foundation. To refresh (about 20 minutes, as the importer
paces its requests):

```sh
npm run import
```

`data/shows.json` holds the shows and setlists; each year's notes are in
`data/notes/YYYY.json`, loaded only when one of that year's show pages opens.

**Photos** come from the [Phish category on Wikimedia
Commons](https://commons.wikimedia.org/wiki/Category:Phish), under CC BY,
CC BY-SA or public-domain terms. They're matched to shows by hand-written rules
in `scripts/import-photos.js`, because the photos' own dates are often wrong.
Where a photo is from a run of shows (a festival, a residency) and the night
isn't known, the show page says so. There are 190 photos of 34 shows so far;
a new series on Commons needs a new rule. To refresh:

```sh
npm run import:photos
```

phish.in doesn't record segues between songs, so unlike Deadbase there are no
segue charts; tags take their place.

## Deploying

GitHub Pages serves only static files, so the Pages build runs the API in the
browser instead of on a server. `npm run build` copies `public/` into `dist/`,
along with the API code (`src/api.js`, `src/data.js`) and the data, and swaps
the front end's `fetch` for a direct call into that code. Pages, charts and
links behave the same as with the Express server.

`.github/workflows/pages.yml` runs the tests, builds, and deploys to Pages on
every push to `main`. The repository's Settings → Pages → Source must be set
to **GitHub Actions**.

## API

| Route | Returns |
|---|---|
| `GET /health` | `{ status: "ok" }` |
| `GET /api` | service name, version, and where and when the data was fetched |
| `GET /api/years?<filters>` | `[{ year, count, months }]` for every year 1983–2026, counting only matching shows; `months` is 12 per-month counts, January first |
| `GET /api/shows?<filters>` | summaries of the matching shows, oldest first; add `sets=1` to include each show's `sets` |
| `GET /api/shows/:id` | one show with its `sets[{ label, songs[{ name, slug, also, duration, tags, notes }] }]`, tags and notes, taper notes, cover art, `gallery` of photos, and `prev`/`next` ids |
| `GET /api/songs` | `[{ slug, name, artist, count, first, last }]`, where `first` and `last` are show ids and `artist` is set for covers |
| `GET /api/songs/:slug` | a song, its Jam Charts count, and every show it was played at |
| `GET /api/tours` | `[{ slug, name, count, first, last }]` in date order |
| `GET /api/tags` | `[{ slug, name }]` for every tag |
| `GET /api/stats?<filters>` | totals, song rotation, Jam Charts leaders, show features, openers, encores, places, venues and records for the matching shows |

`/api/years`, `/api/shows` and `/api/stats` take the same filters, and they
combine:

- `year`, or `from` and `to`: inclusive date prefixes such as `1997`, `1997-11`
  or `1997-11-22`.
- `song`: a song slug. `tag`: a tag slug, on the show or any of its songs; with
  `song`, it must be on that song (`song=tweezer&tag=jamcharts`).
- `tour`: a tour slug. `venue`: a venue slug (`hampton-coliseum`), which
  follows a venue through its renamings.
- `city`, `state`, `country`: exact matches (`country=US`).
- `q`: matches any part of the date, venue, city, state, country or tour.

The stats leave out untitled jams, banter, narration, intros and soundchecks,
which are parts of a show rather than songs.

Show ids are the date (`1997-11-22`).
